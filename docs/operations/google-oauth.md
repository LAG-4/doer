# Gmail OAuth setup

The Gmail tool uses a Google OAuth **Desktop app** client. Create a Google Cloud project, configure its OAuth consent screen, enable the Gmail API, and request the `gmail.send`, `openid`, and `email` scopes. Add test users while the consent screen is in testing. Download the client JSON when creating it. Set `DOER_GOOGLE_OAUTH_CLIENT_ID` and `DOER_GOOGLE_OAUTH_CLIENT_SECRET` in the environment that launches the Doer server or desktop app. For development, put both values in the repository's gitignored `.env.local`, or set them in the same shell before starting the app. Restart Doer, then use **Settings → Integrations → Tools → Gmail** on the host computer.

Doer uses a one-time state and PKCE verifier with a loopback callback at `http://127.0.0.1:<server-port>/api/integrations/gmail/callback`. The client secret is sent only to Google's token endpoint. The refresh token is stored in the host's existing restricted server secrets directory. Keep the client JSON and `.env.local` private. Configure and review the OAuth consent screen and Google's applicable verification requirements before distributing this integration to users outside your test group.

If Google says the app has not completed verification during development, check **Google Auth platform → Audience** in the same Cloud project as the desktop client ID. Use **External → Testing** and add the exact Google account used for sign-in under **Test users**. In **Data Access**, declare `https://www.googleapis.com/auth/gmail.send` alongside `openid` and `email`. A listed tester may still see Google's unverified app warning and can continue only after reviewing that this is their own test app. Public use of the send scope requires Google's sensitive-scope verification.
